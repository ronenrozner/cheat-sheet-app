 Findings (unchanged from before; still valid)

 1. i18n not wired. src/locales/ has only .gitkeep; no en-US.json. Strings are hard-coded in
 App.svelte/SearchBox.svelte. Expected (later task), but "UI fully string-resolved" acceptance isn't met.

 2. No first-run seeding in the frontend. Wait — this is now partially addressed. The Rust side seeds the folder
 (src-tauri/src/seed.rs), but the frontend App.svelte still falls back to a hard-coded stub loader. So the HUD shows
 the sample body while SheetView shows "No sheet selected" and the Sidebar is empty. The Rust seeding is real; the
 frontend just doesn't consume it yet.

 3. CSP is null. tauri.conf.json sets "csp": null. The spec says "keep Tauri's restrictive CSP." Real protection is the
 <iframe sandbox="allow-same-origin"> (no allow-scripts, so scripts can't run). Safe today, but contradicts the stated
 boundary.

 4. matchCount reactivity is fragile. App.svelte uses let matchCount = $derived(...) and passes it to SearchBox. Works
 now but could break on a Svelte upgrade — verify after any upgrade.

 5. Settings write path is convoluted. save() calls store.set(...) to sync the store-plugin cache, then does its own
 atomic temp+rename to the same file. Content matches (no data loss), but the atomicity guarantee is muddied by the
 plugin's own write. Worth simplifying.

 6. Redundant onMount in App.svelte. refreshBody() runs in both onMount and $effect; $effect already fires on mount, so
 the onMount call is dead. Minor.

 7. Terminology: "upstream" = two things. Code upstream = downloaded snapshot dir. Spec/intent "upstream" = GitHub
 repo. Confusing. Minor.

 8. Ask-first: include_dir dependency. Added for seeding. Small, well-maintained. Flagged in spec; your call to keep or
 swap to include_str!.

 Not issues: no LICENSE/NOTICE yet (Task 15, expected); download/online-viewing correctly deferred; SourceMode::Both
 scans an empty upstream dir until download exists.
